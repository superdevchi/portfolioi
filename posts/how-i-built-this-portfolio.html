How I built this portfolio

  • Meta
  • AI
  • Web

I built this site with AI on purpose, and I want to be straight about how. I wrote the content, made the calls on structure and design, and used Claude to write and review most of the code. That is how I work on real projects now, so it would be odd to pretend otherwise here.

The constraints

I gave myself three rules:

  • No build step. Plain HTML, CSS and JavaScript, so the site runs straight from GitHub Pages and anyone can read the source.
  • Content visible first. Animations are an extra. If JavaScript fails, every word is still on the page.
  • Easy to publish. Writing a post should mean adding one file, not fighting a framework.

How the blog works

Each post is its own HTML file in posts/. A short list in posts/posts.js holds the title, date and tags for each one. The homepage and the blog page both read that list, so publishing is two steps: copy the template, add one line.

What I took from other portfolios

I studied a few engineers' sites before rebuilding mine. The good ones shared three habits: one visual that actually explains their work, numbers next to claims, and projects you can open to see the problem, the work and the result. The diagram on my homepage is Silistudio's real architecture for that reason. You can drag it.

What I would do differently

I would have started with the writing section. A portfolio shows what you have built; a blog shows how you think, and that is usually what an interview is trying to find out.
